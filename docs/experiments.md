# Эксперименты

Запуск производится из корня репозитория.

```bash
cmake --preset release
cmake --build --preset release
build/release/mst benchmark --config benchmarks/configs/coursework.conf --output /tmp/coursework.csv
```

## Конфигурация

Конфигурационный файл содержит по одной директиве на строку. Пустые строки и строки, начинающиеся с `#`, игнорируются. Пути графов разрешаются относительно конфигурации. Пути с пробелами можно заключать в двойные кавычки.

```text
repetitions 11
warmups 2
memory_limit_bytes 536870912
exchange_limit 2000000
start 1
path 1 6
file "../../examples/chapter1.txt" int64
case sparse 1000 2000 int64 42 -100 100 mt19937
case dense 500 density=0.75 double 42 -10.5 20 philox
case chain 10000 auto int64 42 -100 100 mt19937
```

`case` задаёт семейство, `n`, количество рёбер, плотность или `auto`, тип веса, seed, нижнюю и верхнюю границы веса и движок. Число рёбер по плотности округляется до ближайшего целого от `n(n−1)/2`. Для некоторых семейств число рёбер задано конструкцией. Цепь, звезда и дерево имеют `n−1` рёбер, полный граф — `n(n−1)/2`. В семействе `disconnected` последняя вершина изолирована, а рёбра выбираются среди остальных. `signed_weights` включает ноль при наличии ребра и отрицательный вес при наличии двух рёбер. `equal` использует один вес на весь граф.

Случайный связный граф начинается с дерева. Для каждой новой вершины выбирается один из её предшественников. Дополнительные рёбра выбираются алгоритмом Флойда из рангов отсутствующих пар. При высокой плотности выбирается меньшее дополнение, затем делается проход по пространству рангов. Это исключает повторные попытки при добавлении рёбер в почти полный граф. Результат воспроизводится при одинаковых параметрах, версии программы и реализации стандартной библиотеки. Стандартные распределения могут выдавать другие значения на той же последовательности движка в другой реализации библиотеки.

Предел памяти задаёт оценку до выделения памяти. Генерация и рабочий набор оценены из расчёта 192 байта на вершину и 192 байта на ребро. Файловый импорт проверяет заголовок по оценке 32 байта на вершину и 128 байт на ребро. Эти числа служат для предварительного допуска. Измеренные байты получаются отдельным запуском с PMR.

## Время

Сначала выполняются два прогрева, затем 11 измерений по умолчанию. Границы интервалов фиксирует `steady_clock`. Для файловых случаев `read` включает открытие, чтение и проверку черновика. `prepare` включает создание массива рёбер и CSR. Чтение повторяется с обычным файловым кэшем ОС.

Обе стратегии работают на одном графе. Порядок их вызова меняется на каждом повторе. `prim` включает работу кучи, `kruskal` — сортировку и операции DSU. Для обеих стратегий учитывается одинаковая стадия создания остова, его CSR и суммы. `path_prim` и `path_kruskal` измеряют DFS и формирование маршрута после построения обоих деревьев. По умолчанию начало Прима — вершина 1, путь ищется из вершины 1 в `n`. В измеряемой части построения отключены трассировка, PMR-счётчики и независимая валидация.

Агрегаты содержат минимум, медиану и максимум в наносекундах. Если повторов чётное число, медиана округляется вниз до целой наносекунды. `*.raw.csv` хранит одно время для каждого измеренного повтора и этапа. Несвязные графы имеют строки времени построения с ошибкой и статусом `disconnected`. Время поиска пути для таких графов отсутствует.

## Память и валидация

После замеров времени измеряется одна отдельная прогонка выделений. `TrackingMemoryResource` подсчитывает запрошенные у ресурса байты, текущий и пиковый объём, суммарный объём и количество выделений и освобождений. `prepare` измеряет создание экземпляра графа, включая временные данные построения CSR. У алгоритмов `scratch_peak_bytes` отражает рабочие выделения, `result_peak_bytes` — выделения результата, `peak_memory_bytes` — реально наблюдавшийся совместный пик этих двух ресурсов. `combined_peak_bytes` учитывает одновременно живой исходный граф и ресурсы алгоритма, включая отдельно наблюдавшийся пик подготовки графа. Пики отдельных ресурсов могут наступать в разное время.

Обычные контейнеры черновика, DFS и проверки, стек, расходы аллокатора и RSS процесса лежат за пределами PMR-замера. Для `read` и `path_*` поля памяти пустые.

`valid_exchange` означает полную проверку, включая условие обмена. Если `n × m` превышает `exchange_limit`, применяется структурная проверка обоих остовов и сравнение их весов. Такой результат помечается `valid_structure_only`. Полная проверка доступна в `mst compare` и `mst solve --validate`.

Каждый выходной CSV заменяется после успешной записи временного файла. Основной CSV публикуется после обоих сопутствующих файлов. При сбое во время публикации нескольких файлов повторите экспорт, чтобы получить согласованный комплект.

## Результаты от 25 ноября 2026 года

Конфигурация [coursework.conf](../benchmarks/configs/coursework.conf) выполнена на AMD Ryzen 5 7430U с 15 736 900 кБ оперативной памяти. Система — Omarchy, ядро Linux 7.2.15-5-omarchy x86-64. Сборка — GCC 16.2.1, Portable, Release, `-O3 -DNDEBUG`.

Серия заняла 25,7 с и охватила 35 конфигураций. Всего получено 176 агрегированных строк и 1 936 отдельных замеров. Оба алгоритма дали одинаковый вес во всех 34 связных случаях. Условие обмена проверено для 20 графов, структурная проверка со сравнением весов выполнена для 14. Несвязный граф дал ожидаемую ошибку у обеих стратегий. Медианы, минимум и максимум сверены с сырыми замерами.

| Разреженный | 100 000 | 100 000 | 52,016 | 36,838 | 7 365 496 | 9 599 960 |

Пики в таблице относятся к рабочим контейнерам и результату одной стратегии. Для графа с миллионом рёбер совместный пик с исходным графом составил 56 488 576 байт у Прима и 57 599 968 байт у Крускала. Относительная скорость стратегий менялась с размером и плотностью графа в этой серии.
