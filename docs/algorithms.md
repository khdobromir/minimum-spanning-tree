# Алгоритмы

Все рёбра сравниваются по `(weight, min(u, v), max(u, v))`. Пара концов различает любые два ребра с одинаковым весом простого графа. Это обеспечивает строгий детерминированный выбор при любой перестановке входных строк. Прим сохраняет порядок принятия для выбранной начальной вершины.

## Прим

Алгоритм включает стартовую вершину, затем помещает в двоичную кучу инцидентные рёбра к ещё не включённым вершинам. Ребро попадает туда при включении первого из его концов. При включении второго конца условие добавления уже ложно. При извлечении ребра из кучи оба конца иногда уже включены. Такое ребро пропускается, иначе меньшее по ключу ребро пересекает разрез и безопасно расширяет остов. Пустая куча до принятия `n − 1` рёбер означает несвязный граф.

Просмотр смежности занимает `O(n + m)`, операций кучи не больше `2m`. С учётом создания результата время составляет `O(n + m log(m + 1))`, дополнительная память — `O(n + m)`.

## Крускал и DSU

Крускал сортирует идентификаторы по ключам рёбер исходного графа. DSU отслеживает компоненты принятого леса. Ребро между разными компонентами добавляется, после чего компоненты объединяются. Ребро внутри одной компоненты образует цикл и отклоняется.

Поиск корня итеративный со сжатием пройденного пути. Объединение присоединяет меньшее множество к большему. Сочетание эвристик даёт амортизированное время `O(α(n))` на операцию. Время Крускала составляет `O(n + m log(m + 1) + m α(n))`, дополнительная память — `O(n + m)`. Для связного простого графа с `n ≥ 2` оценки времени обоих алгоритмов упрощаются до `O(m log n)`.

## Построение результата и суммы

Оба алгоритма сохраняют порядок принятия рёбер. Для суммирования они отдельно сортируют идентификаторы выбранных рёбер по общему ключу. Одинаковый порядок устраняет различие из-за порядка обхода. Сортировка результата требует `O(n log n)` времени и укладывается в приведённые оценки для связного графа. Индекс дерева строится за `O(n)`.

Для `int64` проверяется каждое промежуточное сложение. Выход за диапазон возвращает `weight_overflow`, даже если после последующих слагаемых сумма снова поместилась бы в тип. При трассировке целочисленный префикс считается в двух 64-битных словах и показывается как `overflow` только на шагах, на которых он выходит за диапазон `int64`. Вещественное накопление использует `long double` и поправку Ноймайера. Проверяются конечность промежуточных значений и конечность исправленной суммы. Сравнение итоговых вещественных весов использует абсолютный и относительный допуски по `10⁻¹²`. Ключи рёбер и условие обмена сравниваются без допусков.

## DFS пути

Стек, массив посещений, предшественники и идентификаторы рёбер перехода формируются при каждом запросе. После достижения цели последовательности разворачиваются. Сумма считается в направлении от начальной к конечной вершине. Для запроса из вершины в неё же результат содержит только эту вершину и нулевой вес. Время и дополнительная память составляют `O(n)`. Для исходного графа с рёбрами весов 2, 2 и 3 остов выбирает два ребра веса 2. Путь по остову весит 4 при наличии прямого ребра исходного графа веса 3.

## Независимая проверка

Проверка восстанавливает множество рёбер кандидата, проверяет их принадлежность исходному графу и сравнивает веса. DSU обнаруживает циклы и проверяет связность, а сумма вычисляется заново. Для каждого ребра вне дерева DFS восстанавливает путь между его концами. Если хотя бы одно ребро этого пути строго тяжелее, его замена улучшает кандидат. Максимум начинается с наименьшего значения типа веса. Полная проверка требует до `O(mn)` времени.

Перебор ограничен количеством сочетаний. Он перечисляет подмножества рёбер размера `n − 1` и отбрасывает циклические. Для целых весов сравнение кандидатов использует точную двухсловную сумму. Затем вес победителя пересчитывается по обычному правилу промежуточных переполнений. Это позволяет сравнивать небольшие графы с эталоном независимо от реализации Прима и Крускала.
