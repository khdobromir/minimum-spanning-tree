# Возможности C++

Проект собирается в режиме C++26 во всех пресетах. CMake компилирует пробы библиотечных API и проверяет соответствующие feature-test macros. Профиль Full C++26 дополнительно требует успешных проб рефлексии и контрактов. GCC 16 передаёт `-fcontracts` при компоновке, чтобы драйвер подключил библиотеку обработчика нарушений.

GCC 16 Full использует `-freflection`. Portable содержит фиксированные таблицы имён. |

Full использует семантику `enforce`, Portable — `assert` в сборках с включёнными assertions. Ошибки пользовательского ввода обрабатываются одинаково. |

## Проверенные ограничения

Для Full C++26 выполнена пробная сборка именованного модуля `mst.core` через CMake и Ninja. GCC 16.2.1 создал интерфейс модуля, но компиляция отдельного импортирующего файла с инстанцированием `GraphBuilder<long>` и `PrimAlgorithm<long>` завершилась конфликтами объявлений `std::source_location` и `std::contracts::contract_violation`, а также ошибкой декомпозиции библиотечного `tuple`. Оба профиля используют заголовки.

Константное применение `inplace_vector` в проверке ограничено поддерживаемым тривиальным типом. Рабочие токены со `string_view` используются во время выполнения. Для идентификаторов хватает стандартного вывода типов и явных конструкторов. Дополнительные deduction guides не понадобились.
